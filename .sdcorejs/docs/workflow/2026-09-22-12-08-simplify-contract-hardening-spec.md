# Spec - Simplify contract hardening - 2026-09-22

**Draft awaiting explicit approval.** This is a scoped authoring change to sdcorejs-simplify and its direct consumers. No implementation authority is inferred from this draft.

## Problem and current evidence

At clean main `ac820d70bd247a04f977aab9bbb864f6a054acb7`, the existing two simplify suites pass 18/18. The helper trusts declared files/pass metadata, does not inspect repository content, and accepts a different schema from verification.md. It also requires post-edit evidence before granting write authority.

An offline temporary regression suite produced **25 tests: 18 FAIL, 7 PASS**, exit 1, on both Node 22.14.0 and supported Node 24.19.0. The failures exercise empty/out-of-scope writes, undeclared real generated/protected writes, traversal/absolute paths, another real Git root, a Windows junction escape, missing/blank commands, changed bytes with the same claimed HEAD, concealed Analyze writes, lowercase failed passes, pass numbering, and reset recursion metadata.

The seven safe controls reject explicitly declared generated/protected paths, differing owner IDs, declared Analyze writes, uppercase FAILED without rollback, three ledger entries, and recursion depth 2. These protections must survive. Direct payload probes also show documented v1 is rejected by the helper and a green before-only input is blocked for missing after evidence.

Diagnostic limitations: these tests prove helper acceptance/rejection and real local filesystem facts in temporary Git repositories, not live agent behavior or full runner integration. Legacy positive receipts were intentionally synthetic to match the current test fixture; they must not become v2 evidence. Temporary repositories contain no commits. Final regressions must execute real commands and derive current snapshots.

## Requirements

- R-001 - Revalidate the current checkout and reproduce each reported simplify enforcement gap with paired safe controls.
- R-002 - Use one versioned simplify_context schema across documentation, executable helpers, fixtures, and direct consumers.
- R-003 - Separate preflight write authority from postflight verification without fabricated future receipts.
- R-004 - Derive actual file and hunk changes from repository evidence and enforce the intersection of user, plan, eligible-source, and protected boundaries.
- R-005 - Bind focused command evidence to its actual owner, cwd, source content, scope, and execution result; a matching HEAD alone is insufficient.
- R-006 - Enforce bounded passes, rollback, Analyze-only, evidence invalidation, and nonrecursive downstream delivery; regenerate mirrors from canonical sources only.

## Proposed contract decisions

- D-001 - schema_version: 2; documented field families and lowercase result enums; explicit read-only v1 adapter. Neither incompatible v1 shape proves authority or content-bound verification. Status: proposed; resolved only by approval of this spec.
- D-002 - Analyze-only; remove the limited-write override branch. The user permits choosing whether to retain the override; removing it keeps the write contract bounded. Status: proposed; resolved only by approval of this spec.
- D-003 - Reuse approved-artifact hashing and existing repository-snapshot/command-receipt conventions; obtain content and execution facts through the host capture/runner. A caller declaration or self-computed hash is not an independent observation or an approval. Status: proposed; resolved only by approval of this spec.

### Canonical runtime payload

Use one schema v2 definition owned by the simplify contract. verification.md documents the same accepted payload; tests parse its runnable example rather than substituting a different private payload. Preserve the documented field families `artifact_identity`, `source_revision`, `target_root`, `scope`, `preserved_surfaces`, `passes`, `result`, `verification`, and `artifact_context`. Add explicit phase, authority references, snapshot references, and workflow provenance.

Use `scope.requested`, `scope.eligible_files`, and `scope.eligible_hunks` with repository-relative paths and snapshot-bound line ranges. Use one `passes[].changed_paths` field derived from observed deltas. Command results use `passed | failed | not-run`; behavior coverage remains distinct from process result. Keep separate run/result status, freshness, and write_authorized; a passed command never means arbitrary semantic equivalence.

Only preflight may emit write_authorized=true. Preflight consumes current owner/root identity, user authority, an actual approved plan step when applicable, eligible files/hunks, protected inventory, a captured dirty baseline, and executed before evidence. It requires no after evidence. Postflight consumes the preflight identity and actual after observations; it may attest only the focused checks that ran, never retroactively authorize a write.

Use an explicit read-only legacy adapter for both historical documented v1 and helper-fixture v1. Preserve legacy metadata/limitations, reject conflicting representations, and require fresh v2 preflight/evidence for any write or current pass. Never synthesize receipts, approval, timestamps or missing content hashes. Existing approved spec/plan snapshots remain byte-for-byte unchanged.

### Actual scope and preservation

Enforce user-authorized scope intersected with approved-plan allowed paths (when present), eligible source/hunks, and protected exclusions. A repository-derived inventory and before/after byte/mode/index deltas must cover the observed Git root, including untracked changes and omitted generated/protected paths; declared changed_paths is a checked projection, never the discovery input. Capture relevant ignored output boundaries explicitly or block when completeness is unknown.

Reject unsafe relative paths, Windows/POSIX/UNC absolute paths, traversal, sibling-prefix tricks, ambiguous roots, nested repository ownership mismatch, and symlink/junction escape. Recheck containment at capture/write boundaries. Never follow an unresolved path to authorize edits. Eligible source is established from repository purpose/build/convention evidence, not extensions alone.

Bind selected hunk ranges to baseline content, including insertions/deletions. Preserve baseline user-owned bytes and staged state. Expansion requires path/hunk/reason/evidence impact and authority from the original user and any applicable approved plan; no silent subset replacement or adjacency exception bypasses approval.

Preserve all existing protected surfaces and 2 passes / 5 files per pass / 8 total files / 20 hunks limits. A failed pass needs an observed exact scoped rollback, not reverted:true alone. Unknown preservation checks block Apply or postflight. Snapshot comparison observes boundary states; it is not an OS sandbox or a claim to intercept arbitrary external writes. No observer completeness means no write authority.

### Evidence and downstream consumers

Reuse existing approved-artifact hashing/verification and typed snapshot/command-receipt infrastructure from approved-artifact.mjs and repair-contract.mjs. Current repair snapshots are revision-oriented and validators do not capture working-tree bytes: add only the working-tree/runner adapter needed by simplify, with a host-issued evidence boundary. Hashes provide integrity and identity, not independent proof of origin.

Every receipt binds a nonempty exact command, argv where available, real cwd, owner/Git root, scope/hunks, exit code and derived result, source revision and actual content fingerprint, output digest and execution timing. Capture before/after the command to reject source mutation during verification. Test/config/oracle changes affecting coverage invalidate evidence even with unchanged HEAD.

Default missing behavior oracle to Analyze-only. Remove new limited-write override authorization. Retain old limited evidence only as explicitly limited historical input; neither adapter nor ship may promote it. Report PASS only as coverage by the current focused commands.

Consumers test, review, repair-loop, ship and portable handoff use the same validator and identity fields. A relevant write invalidates affected test/review/ship evidence until fresh runs are appended. Ship blocks absent/stale/limited verification, protected drift, failed unrolled passes and false claims. Repair preserves the original simplify context and cannot reset the workflow history to invoke simplify again.

## Architecture gate, assumptions and risks

Architecture classification: **required**, signals public-api-contract and security-trust-boundary. Freeze a lean schema/authority/capture-consumer boundary after spec approval and before the implementation plan. This does not expand the task beyond simplify hardening.

Existing primitives are reusable but currently do not themselves observe all working-tree writes. The plan must make the trusted capture/runner explicit, fail closed when it is unavailable, and avoid self-authorized receipts. Cross-language semantic preservation cannot be proven generally: preservation checks plus scoped tests provide bounded evidence only. Symlink/junction behavior is verified on this Windows host; unavailable platform cases must remain NOT RUN with reason.

The v1 write-authorization contract intentionally becomes incompatible: callers must migrate through fresh v2 preflight. Read-only diagnostics remain possible. Removing the limited-write override is a proposed compatibility decision requiring this spec approval.
