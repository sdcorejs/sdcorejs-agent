# Public Websites and Landing Pages

Source/status: SDCoreJS-authored content/task heuristics. Existing approved
Next.js website features, content and assets remain the implementation scope.

### UX-WEB-PURPOSE - Structure around audience and content

- Applies: public websites, landing pages and mobile public content.
- Excludes: enterprise work surfaces; never use this as an unmatched portal fallback.
- Do: identify audience, page purpose, primary action and available evidence.
  Organize content so users can understand the offer, inspect relevant proof
  and act. A hero can help a landing page; it is not required for every page.
  Preserve existing brand/type/tokens for additions. Choose spacing and reading
  width for comprehension rather than importing back-office density.
- Avoid: invented testimonials/numbers, decorative section quotas, giant headings
  obscuring the useful content, or a mandatory Hero + Features + CTA recipe.
- Verify: information order with real content, meaningful heading/link structure,
  long translations, mobile reading and the route to the primary action.

### UX-WEB-ACTION - Make commitments clear and truthful

- Applies: approved CTAs, signup/contact flows and conversion improvements.
- Excludes: unapproved forms, tracking, analytics, CMS, pricing or integrations.
- Do: name what the action does, its relevant cost/commitment and the next state.
  Keep repeated CTAs consistent, contact/submit feedback truthful, and persistent
  banners/actions from covering content or focus. Use the smallest interaction
  needed; preserve actual server/client boundaries and performance constraints.
- Avoid: fake success on a form, coercive default choices, adding tracking from a
  design suggestion, or importing a font/icon/motion package to imitate upstream.
- Verify: each approved action's destination, submission/pending/error/success
  states, keyboard behavior, narrow-screen occlusion and actual integration result.
